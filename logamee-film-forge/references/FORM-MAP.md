# Content → Visual Form Mapping Table

> 当 AI 理解到"这段内容想让观众形成什么心理模型"后，查这张表决定用什么视觉形式。
> 这不是图表菜单。不要看到几个名词就套卡片，不要看到步骤就套箭头。

---

## 如何使用这张表

AI 拿到一段原文后，依次走五个问题：

```
原文: "翻来覆去就这六条。无记忆、概率性、涌现、幻觉、推理、上下文"

Q1: 观众看完这页应该形成什么理解？
    这不是一串词，而是 AI 系统的六个底层约束。

Q2: 这些概念之间是平等并列、层级递进，还是互相牵制？
    如果是平等底层约束 → 结构关系 / 中心辐射
    如果是从底层到上层能力 → 层级结构
    如果是造成问题的根源 → 因果网络

Q3: 本页的视觉焦点是什么？
    不是六个词都一样亮，而是先让观众看到“底层约束”这个整体。

Q4: 读对应行的「视觉形式」和「工具」：
    中心辐射（Hub-spoke 图） · 工具: SVG 内联

Q5: 生成语义级动画意图：
    先出现中心命题，再让六个约束环绕建立，最后用连线表达它们共同限制系统行为。
```

↓ Slide Spec 里的「形式」和「工具」就定了。

## 语义动画词典

写进 `narration-pages.md` 的是动画意图，不是实现细节。HTML 阶段再用 GSAP 落地。

| 内容关系 | 动画意图 | 禁止 |
|---|---|---|
| 因果 | 原因出现，机制生长，结果被点亮 | 三者同时淡入 |
| 对比 | 两侧建立差异，重点侧最后加权 | 两列同时出现且权重相同 |
| 递进 | 从底层到上层逐步建立 | 先出现结论再补过程 |
| 反转 | 建立预期，停顿，替换为真实结论 | 直接把反转前后并排展示 |
| 层级 | 底层先稳住，上层依托出现 | 层级同时出现 |
| 系统 | 边界、模块、连接依次建立 | 先画满复杂网络 |
| 混乱→有序 | 散乱元素按逻辑归位 | 一开始就整齐摆好 |
| 误区纠正 | 错误观点退场，正确观点补位 | 错误和正确同等强调 |
| 冲突 | 两股力量形成张力，最后显示结果 | 只做普通双栏 |
| 结论/金句 | 留出停顿，再逐词/逐块强化 | 小字堆叠 |

## Cognitive Form Map

这一节不是增加图表类型，而是约束“观众理解如何被画面改变”。生成 `visual-logic.md` 时，优先从这里选择认知映射，再回到下面的表选择具体视觉形式。

### 画面文字与字幕分工

- Use When: 口播和字幕已经完整承载解释，画面不需要把所有细节再写一遍。
- Viewer Starts With: 观众需要先看懂这一页在表达什么关系。
- Viewer Ends With: 观众能从画面理解主意思；如果想知道例子、原因、限定条件，再听口播或看字幕。
- Visual Primitive: 关键词、数字、轴线、节点、路径、位置关系、少量短判断。
- State Contract: 每个状态都要保留足够留白；最终落定状态必须能截图阅读；细节信息不进入屏幕，交给 narration/subtitles。
- Avoid: 把字幕改写成屏幕段落；为了放下所有文字而缩小字号、压缩间距、让节点互相遮挡。

### 散乱名词 → 能力主线

- Use When: 内容表面上是一堆新名词，真正要讲的是它们之间的递进关系。
- Viewer Starts With: 又多了很多概念，不知道先学什么。
- Viewer Ends With: 新概念长在旧能力之上，不是每次从零开始。
- Visual Primitive: 孤岛节点、主线、旁支、终点加权。
- State Contract: 散乱可读 → 主线建立 → 旁支降低权重；最终节点不得重叠。
- Avoid: 只把名词排成列表，或者把所有关系线平均展示。

### 远目标 → 小步推进

- Use When: 内容要把巨大压力拆成可执行的小步。
- Viewer Starts With: 目标太远，感觉无法开始。
- Viewer Ends With: 目标没有消失，但下一步变小、变清楚。
- Visual Primitive: 长距离、分段路径、小步高亮。
- State Contract: 长距离先压住画面 → 长距离退淡 → 小步逐段出现；最终焦点停在可执行的小步。
- Avoid: 把隐喻画成旅行、风景、目的地，或者只做两个数字卡片。

### 专家观点 → 知识结构接收

- Use When: 内容引用专家、访谈或外部观点，但重点不是名人背书。
- Viewer Starts With: 听到观点，只能觉得“很深”。
- Viewer Ends With: 观点被放进已有结构，因此能理解，也能判断。
- Visual Primitive: 外部输入、知识结构、对应槽位、判断焦点。
- State Contract: 观点进入 → 结构亮起 → 观点归位 → 判断加权。
- Avoid: 真人照片、名人海报、把观点只做成三条引用。

### 旧载体 → 内容匹配载体

- Use When: 内容要说明图文、视频、动画、练习不是功能堆叠，而是由内容类型决定。
- Viewer Starts With: 形式很多，像功能列表。
- Viewer Ends With: 不同内容自然选择不同载体，学习路径更连贯。
- Visual Primitive: 旧状态、删除线、教材页面、阅读路径、载体接入点。
- State Contract: 纯文字/纯视频短暂出现 → 旧状态被一条删除线划掉，明确表示“不采用这种唯一载体” → 教材页面展开 → 不同载体沿阅读路径接入。旧状态不能只靠变灰表达否定；如果保留在最终画面里，必须仍然可读，并且用删除线表达否定。打叉只在语义确实是“错误/禁止”时使用。
- Avoid: 四宫格功能卖点、并列图标、产品宣传式卡片。

### 静态目录 → 学习路线

- Use When: 内容表面是章节、阶段、目录，真正要表达能力递进。
- Viewer Starts With: 目录很长。
- Viewer Ends With: 章节被理解为一条从基础到目标能力的路线。
- Visual Primitive: 压缩数字、阶段节点、路线生长、终点加权。
- State Contract: 数字或目录入口 → 阶段展开 → 路线连通；最终阶段标签和字幕不得互相压住。
- Avoid: 完整念目录、静态列表、阶段权重完全相同。

### 当前结构 → 未来增量

- Use When: 内容要讲持续更新、技术演化、长期维护。
- Viewer Starts With: 技术还会变，所以仍然焦虑。
- Viewer Ends With: 更新不是散乱追加，而是沿同一条主线继续生长。
- Visual Primitive: 稳定主线、未来分支、更新带、开放终点。
- State Contract: 当前主线稳定 → 未来节点从主线生长 → 更新承诺落定；最终所有未来节点必须分区清楚。
- Avoid: 口号式结尾、未来项堆成清单、更新节点互相遮挡。

## 工具优先级

- 结构和静态图形优先用 HTML/CSS 布局、内联 SVG、Canvas。
- 所有动画统一由 GSAP Timeline 驱动。
- 第三方图库只负责渲染关系或数据，不负责动画编排。
- 任何第三方库都必须本地化，不能 CDN。
- 表中“纯 CSS”指布局实现，不指 CSS keyframes 动画。
